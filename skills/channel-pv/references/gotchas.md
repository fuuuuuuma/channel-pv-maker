# 落とし穴（実際に詰まったこと）

## After Effects

- **AE は同じ PC の別の作業と共用していることがある**。`ae build` は、開いているのがこの案件の .aep か空の名称未設定のときだけ作り直す。
  別のプロジェクトが開いていたら何もせずに止まる（BUSY）。勝手に閉じない：持ち主に保存して閉じてもらう。
- **台本を受け付けなくなる**：AE の画面にダイアログ（警告・保存の確認・エラー）が出ていると、外からの台本はすべて止まる。
  画面を見てダイアログを閉じてもらう（画面操作の道具があれば自分で確かめる）。
- **確認用のコマは AE が後から書き出す**（saveFrameToPng は書き終わる前に戻る）。`ae build` は揃うまで待つ。
- **書き出しの設定名は言語で違う**（日本語版「最良設定」「高品質」、英語版「Best Settings」「High Quality」）。render は両方を試す。
- **aerender（コマンドラインの書き出し）が途中で落ちることがある**。`ae render` は AE の画面側のレンダーキューで書き出す（こちらが安定）。
- **空き容量**：ProRes の中間ファイルは 1 秒あたり約 18MB（5 分で 5GB 強）。足りないと途中のファイルが壊れる。`ae render` は先に空きを確かめる。
- **同じ道のファイルを上書きした素材**（作り直した場面など）は、AE が古い中身を覚えていて黒いコマになることがある。名前を変えて読み込む。
- フォントが無いと AE は別の書体で描く。`style.json` の font_* はその PC に入っている PostScript 名に（Mac はヒラギノ・Avenir Next、Windows は游ゴシックなど）。

## ffmpeg・取得

- **ffmpeg は Homebrew などのネイティブ版を使う**（Mac の ~/.local/bin に Intel 版が混ざっていると遅い・落ちる）。`PV_FFMPEG` で指定できる。
- **字幕機能（libass）や文字描き（drawtext）が無い ffmpeg がある**（Homebrew の 8.x など）。だから AE 無しの書き出しも字幕と名前はブラウザで描いて重ねる。
- **yt-dlp**：403・取得の失敗は時間をおいて再実行（fetch は取れた区間を飛ばす）。`yt-dlp -U` で更新。一度に大量に取ると一時的に弾かれる。
- 取得した区間の外を edl.py で使うと「取得した区間の外です」で止まる。edl.py を直したら `prep`（timeline → fetch …）をやり直す。

## 声・文字起こし

- 文字起こしの語の時刻は 0.1〜0.2 秒早く出ることがある。a・b は `prep` の「始め／終わりのそばの語」と `qa` の voices.txt で確かめる。
- 音量の谷だけで語尾を切ると、小さく速い語尾（「〜じゃないですか」）が欠ける。欠けたら audio.json の `force_end` に元動画の秒で終わりを書く。
- demucs が無いと元動画の BGM が声の下に残る。入れられないなら、元動画の BGM が小さい発言を選ぶ。

## ブラウザの描画

- 場面の書き出しは重い（1 秒に 4 コマ撮って重ねる）。8 場面で 5〜10 分。`still` で 1 コマずつ確かめてから全部を書き出す。
- 書体：日本語はヒラギノ（Mac）か Noto Sans JP（Google Fonts から読む・ネット接続が要る）。強調は Noto Serif JP Black。
- 画像が読めないと空白のまま書き出される。`still` で画像が出ているかを必ず見る（道は案件フォルダからの相対）。

## 顔検出

- Mac は Apple Vision（同梱の faces.swift を初回に作る。Xcode のコマンドラインツールが要る）。他は OpenCV。どちらも無いと `faces` と寄りの顔合わせができない
  （寄りは画面の中心へ）。小さい顔（画面の中の画面）は無視する。2 人以上いる絵の寄りは `punch=dict(face='left')` などで話者を指す。

## AI 動画（Higgsfield・Seedance）

- **プリセットを勧められて止まる**（「IN THE DARK」など）：その案件は作られていない。勧められたプリセットの ID を `declined_preset_id` に入れて出し直す。
- 画像を渡すと mode が omni_reference になり、**start_image が 1 コマ目にぴったり来ないことがある**（最初の数コマが別の構図・別の顔）。全コマを並べて使う区間を選ぶ。
- 同時に頼めるのは 8 本ほど（超えると 429）。届いた動画の URL はファイル名と取り違えやすいので、頼んだ順と ID を JSON に控えて落とす。
- 1080p への引き上げ（Real-ESRGAN）は 1 コマ約 0.2 秒＋書き出しで、4 秒の動画 1 本に 1 分ほど。16 本で 15 分前後。

## 書き出し・片付け

- 1080p の PNG 連番は 3 分で 13GB ほど。プレビューのたびに増えるので、版ごとに古い連番を片付ける。
- 片付けは削除ではなく `~/.Trash/<名前>/` へ移し、元の場所と大きさの一覧（元の場所.txt）を残す。ゴミ箱を空にするまで空き容量は増えない（空にするのは依頼主）。
- zsh では `set -- $変数` が単語に分かれない（`a=(${=変数})` を使う）。ファイル名と URL を組にした繰り返しで取り違えやすい。
- Python の multiprocessing を `python3 - <<EOF`（標準入力の台本）で使うと、子の処理が台本を読めず失敗を繰り返して CPU を食い続ける。台本はファイルにしてから実行する。

- **場面の描画が `page.screenshot: Timeout` で止まる**：2 つの案件の `pv.py scenes` を同時に走らせたり、AE の書き出しと重ねたりすると、ブラウザが混んで 1 コマの撮影が遅れる。
  撮影の待ちは 120 秒にしてあるが、描画は 1 案件ずつ・`PV_TABS` は 3 以下で。止まったら、描けていない場面の名前だけ `pv.py scenes <名前...>` で描き直す（描けた場面の .mov はそのまま使える）
- **透明の場面の動画が途中で切れる**（文字の抜きを全面に開いた・全面を塗った所から先が無い）：画面が全部不透明になったコマは、ブラウザが透明の情報なしの PNG で保存し、まとめる段がそこで止まっていた。
  場面は左上の 1 点を常に透明にしてある。描き終わりに「!! … コマで切れた」と出たら、その場面だけ描き直す
- **AE の書き出しが「途中で止まりました」**（空き容量は足りている）：別の案件の `ae build` が、書き出し中のプロジェクトを閉じた。AE は 1 つしか開けないので、
  `ae build`〜`ae render` は案件を 1 つずつ順に。裏で「前の案件が終わったら次」と待たせるときは、待つ目印に他の行にも出る言葉（「跳ね」など）を使わない（先に別の行に当たって、書き出し中に次が始まった）。
  終わりの目印は「== 案件名」の後の行で確かめるか、1 本のスクリプトで順に呼ぶ
- **24p の素材なのにカクつく**：style.json の `fps` が 30 のまま。前のコマとの差（`signalstats` の YDIF）を並べると、30 では 5 コマごとに差が 1.0 前後（同じコマ）が出る。24 にすると消える。
  素材が 25 コマなら 4% 遅くして 24 コマにそろえる（`setpts=PTS*25/24` と `-r 24`）。粒子が毎コマ違うので、`mpdecimate` では重複が見つからない
- **qa の「明るさの跳ね」が暗転の直後の 1 コマ**（例 17→76→17）：黒い幕（glow の `shade: 1`）の `fade_in` が 0 より大きいと、1 コマ目だけ透けて下の映像が光る。幕は `fade_in: 0`。
  `signalstats` の YAVG を前後 10 コマ並べると 1 コマだけ高い所で分かる
- **ピークが 0 dBFS を越えた**（mix.wav は -2.0 なのに書き出しで +0.2）：ffmpeg の aac が強く抑えた音の頭で持ち上がる。書き出しは Mac なら `aac_at`（-1.7 になった）。
  映像を描き直さずに直すなら、映像は `-c:v copy` で音だけ mix.wav から入れ直す
