# channel-pv — 実際の声と映像でつなぐ紹介 PV

YouTube の動画から出演者の発言を選び、その声（元動画の BGM を抜いたもの）と同じ時刻の映像を並べ、
ブラウザで描いた場面（題字・数字・地図・一覧・バナーの壁・声の文字・X の投稿の壁・終わり）と
縦書きの強調テロップで「テレビ CM・広告に出せる水準」の PV を作る。作業はすべて `pv.py` の命令で行う。

## 最初に（道具の場所と点検）

Claude Code では `${CLAUDE_PLUGIN_ROOT}` がプラグインの場所になる。Codex では展開されないので順に探す。

```bash
PV="${CLAUDE_PLUGIN_ROOT:-/nonexistent}/scripts/pv.py"
[ -f "$PV" ] || PV="$(find "$HOME/.codex/plugins/cache" -maxdepth 8 -type f -name pv.py -path '*channel-pv-maker*' 2>/dev/null | head -1)"
[ -f "$PV" ] || PV="$(find "$HOME/.claude/plugins" -maxdepth 8 -type f -name pv.py -path '*channel-pv-maker*' 2>/dev/null | head -1)"
python3 "$PV" doctor
```

以降のコマンドは `python3 "$PV" <命令>`。案件フォルダの中ならどこで実行してもよい。
doctor の「必須」が欠けていたら、入れ方（`pip install -r <プラグイン>/requirements.txt`、Homebrew の ffmpeg・yt-dlp・node）を
利用者に 1 つずつ案内してから進む。After Effects が無いだけなら止まらない（最後に `compose` で書き出す）。

## 進め方（この順で。各段の詳しいやり方は references/ を開く）

1. **下調べ（質問の前に自分で済ませる）** — `init` で案件フォルダを作り、`harvest <チャンネルの URL> --limit 15` で
   動画の一覧・下見・文字起こし・サムネ・チャンネルのアイコンとバナーを集める。題名・概要欄・文字起こしを読み、
   「何のチャンネル／誰が出ているか／強い発言の候補／数字の実績（人数・回数）」をつかむ。参考動画を渡されたら先に見る。
2. **軽い質問を 1 回だけ** — 下調べから作った「構成の案 2〜3 つ」と「見た目の案」を選択式で見せ、目的・長さ・必ず入れる人や言葉・
   最後の一言・素材の使用許可・有料生成の可否をまとめて聞く。→ `references/interview.md`
3. **構成表を作って承認をもらう** — `planning/plan.md` に幕ごとの流れ・使う発言（動画 ID・秒・話者・字幕）・場面・強調・長さを表で。
   ここで「OK」をもらうまで組み立てない（作り直しが一番高くつく）。→ `references/structure.md`
4. **設計図を書く** — `build/edl.py` の「ここから〜ここまで」に line / fx / ai / montage を並べる。字幕は話した言葉に近い形で、
   長い発言は区切って切り替える。強調（縦書き）と同じ言葉は字幕に入れない。→ `references/pipeline.md`
5. **素材の下ごしらえと点検** — `prep`（時刻表→1080p 取得→声の分離→語の時刻→高精度の文字起こし）→ `edges`（元動画の編集点の切れ端）
   → `faces --apply`（黒帯で顔が切れない位置）→ `crops`（完成時に見える絵を目で見る：焼き込みの字幕やラベルが映っていないか）。
   見つかったものは edl.py と framing.json を直して `prep` をやり直す。
6. **場面・強調・音** — `build/scenes.json`（場面の中身）、`build/audio.json`（音楽・効果音の置き場所）を書く → `plan` → `scenes`
   → `telops` → `mix`。場面は書き出す前に `still scenes <名前> 2,5` で 1 コマ見て直す。→ `references/design.md`
7. **組み立てと書き出し** — After Effects があれば `ae build`（確認用のコマ `build/_ae_check/sheet.jpg` を必ず見る）→ `ae render`。
   無ければ `compose`。どちらも `exports/<名前>_<版>.mp4`。
8. **検品** — `qa`（音量・一瞬の閃光や黒・全切り替えの一覧・声の文字起こし）。一覧の目視はサブエージェントに任せられるなら任せ、
   指摘は自分で拡大して確かめてから直す。`preview` でスマホ用の軽い版も作る。→ `references/qa.md`
9. **報告** — 結論を先に。長さ・何を入れたか・変えた所／触っていない所／確認してほしい所。ファイルは絶対パスで。

## 守ること（理由つきの要点。全部は references/rules.md）

- **発言は文脈が通る所で切る**：問いかけ（聞き手の質問）や前置きも使い、話の途中でプツンと切らない。切り取りの飛躍は一番目立つ失敗。
- **元動画の編集点の切れ端（数コマ）を入れない**：元の動画はすでにカット編集されている。頭と終わりがカット境目をまたぐと別の場面が一瞬混ざり、
  テンポが悪く見える。`edges` の指摘は必ず直す。
- **声は必ずフェードで入って出る**（mix が自動で行う）。語尾は余韻が消えるまで伸ばすが、次の言葉の手前で止める。
- **字幕は要約しすぎない**：話した言葉に近い形を 1 画面 1 行で、長ければ切り替える。句読点（。、）は付けない。
- **話している人の顔を映すときは同じ時刻の映像**（差し込みに別の時刻の顔を使うと口と声がずれる）。顔は黒帯や縦書きで隠さない。
- **見た目はブランドに寄せすぎず洗練させる**：ロゴや色は守り、漫画調・ネオン・子どもっぽい装飾に寄せない。1 コマだけの白い閃光は使わない。
- **最後の一言は主役（オーナー・チャンネルの顔）で締める**。ゲストの発言で終わらせない。
- **書き出す前に見る**：確認用のコマ・場面の 1 コマ・切り替えの一覧を自分の目で見てから「できた」と言う。動いたことと見た目が良いことは別。

## 外に出ること・お金がかかること（毎回、先に聞く）

- **素材の権利**：他人のチャンネルの映像・X の投稿・バナーは、持ち主から使ってよいと言われたものだけ使う。下調べの段で確かめる。
- **有料の生成**（AI 動画・画像・音楽・効果音）は、何を・何本・いくらかを見積もって承認をもらってから。上限を決めてもらい、超えそうなら止まる。
  → `references/extras.md`
- YouTube や X への投稿・公開はしない（書き出しまで）。上書きする前は対象を見て確かめる。

## Claude Code と Codex の違い

- 質問：Claude Code は選択式の質問ツール（AskUserQuestion）で 1 回にまとめる。Codex は番号つきの選択肢を本文で出し、返事を待つ。
- 目視の分担：サブエージェントが使えるなら、切り替えの一覧（build/_qa/cut_*.jpg）の検品を任せる（`references/qa.md` に頼み方の雛形）。
  使えなければ自分で全部見る。
- After Effects の操作は同じ（Mac は osascript、Windows は AfterFX.com）。画面にダイアログが出て止まったときの直し方は `references/gotchas.md`。
